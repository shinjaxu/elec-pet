# 宠物自动整理桌面图标

日期：2026-10-22

## 已确认的目标

宠物自主整理散乱的桌面图片、文件、文件夹和快捷方式。只调整图标位置，不改变文件路径，不创建归档目录，不打开、复制、删除或重命名文件。用户不需要点击菜单或启动额外工具；功能随现有桌宠运行。

用户已确认并在实机反馈中修订：键盘空闲 30 秒后开始，键盘输入时暂停，再次键盘空闲后继续，鼠标移动、点击和滚轮不重置计时；宠物逐个抓取、搬运、放下，移动平滑；已经排好的图标不反复搬动，桌面发生变化后只处理需要调整的项目。

沿用 Unity 6000.6.6f1、现有程序化幼龙、透明窗口与主屏幕范围。此规格已由用户审阅通过；实现与验证结果见 docs/verification.md。

## 触发与优先级

- 使用 Windows 键盘事件判断空闲，仅记录活动时间；按下、松开及系统组合键重置计时，鼠标移动、点击和滚轮不参与。按住键盘键时保持忙碌，不能只靠每帧轮询遗漏短击。
- 空闲满 30 秒、宠物可见且未暂停、没有拖拽或互动时，读取桌面快照并生成整理任务。已经在播放的短暂互动动作先结束，整理开始后暂时停止巡游、追鼠标、图标观察和随机动作。
- 新键盘输入立即停止推进动画和新位置写入，保留当前任务与进度；再次键盘空闲满 30 秒并核对快照后继续。普通鼠标操作不暂停整理；明确抚摸和提起仍优先处理。不能把暂停期间的时间补算为搬运位移。
- 桌宠暂停或隐藏时，同样冻结整理；退出时取消尚未执行的任务，不在退出回调继续搬运。初版不保存跨进程任务，重启后按真实位置重新规划。
- 用户提起、抚摸宠物时，取消当前动画和剩余计划，图标保持最后确认的位置；互动结束并再次空闲后从实测位置重建计划，不抢夺用户输入。
- 单次整理完成后恢复现有生活行为。无变化快照不生成任务，周期性读取沿用现有低频节奏，不在每帧完整扫描桌面。

## 分类与布局

按图片、文档、文件夹、快捷方式、其他项目顺序连续分组。快捷方式优先按 Shell 链接属性分类，不跟随目标；普通目录按文件夹分类，系统虚拟项目归其他。图片包括常用位图、WebP、GIF、HEIC、SVG；文档包括常见 Office、PDF、文本和 Markdown，其余文件归其他。具体扩展名表保持小而明确。

同组按显示名称稳定排序，以 Shell 项目标识作同名兜底。项目身份不能使用枚举索引或仅用显示名称，避免扫描顺序变化时搬错图标。

读取 Shell 实际图标间距及工作区，按从上到下、再从左到右的网格分配位置，保留完整图标及文字单元，避开任务栏。组间有余量时留空格，容量紧张时去掉组间空格。位置比较允许少量像素误差，避免 Shell 舍入造成反复整理。

仅规划当前主屏内项目，其他显示器上的项目不纳入计划；占用检查同样尊重现有项目。空间不足时本轮不执行部分溢出的布局，保留现状并显示原因。已经在目标位置的项目跳过；新增项目可能改变后续目标槽位，只搬动目标实际变化的项目。

目标槽位被其他图标占用时，先腾空再搬入；交换或循环占位使用一个空闲网格作临时位置，该搬运也必须由宠物完成。没有可用临时位置时保留现状并等待桌面变化，不把图标叠在一起。

## 搬运动作

每个任务分为走近、抓取、搬运、放下四段。先走到源图标旁，朝向图标并俯身伸爪，再以贴近嘴部的叼持姿态搬运，保留四足行走，最后低头放下。这样适配当前四足模型，避免两只前爪悬空却仍使用四足步态。抓取和放下各约 0.5–0.7 秒，搬运按距离计时，速度约 90 像素/秒，首尾缓入缓出。

搬运期间移动真实 Shell 图标，宠物和图标使用同一条连续轨迹、同一份活动时间。图标保持靠近口部的屏幕偏移，起抓与落地通过插值衔接偏移，避免拾取瞬间跳位。转向沿用现有平滑旋转，头部朝任务目标，身体轻微随步态起伏。

现有 PetMotion 的 88 像素模型安全边距与图标网格边缘不同，整理专用轨迹需要计算可达的宠物位置和受限叼持偏移，不能直接把图标坐标作为宠物中心，也不能改动普通拖拽的安全边距。靠边拾取和放下必须纳入视觉验收。

编辑器提供合成图标和同一套动作的自动演示，不读写真实桌面，便于检查整段动作与中断。Windows 构建才启用真实 Shell 适配器。

## Windows 接口与线程

扩展现有 DesktopIcons 适配器，读取项目身份、显示名称、分类属性、位置、间距和排列状态，通过 IFolderView.SelectAndPositionItems 设置位置。只设置位置，不选择项目、不获取焦点、不模拟鼠标拖拽，不跨进程读写 Explorer 内存。

GetAutoArrange 的 S_OK 表示自动排列开启，S_FALSE 表示关闭，必须保留 HRESULT，不能当作普通无返回值 COM 方法。自动排列开启时不启动搬运，不擅自关闭系统设置，状态提示一次并等待设置或桌面变化。

“与网格对齐”对连续位置写入的影响需要在真实 Windows 验证。优先使用位置接口实现连续移动；若需要临时关闭吸附，仅在当前搬运期间保存并修改对应标志，暂停、结束、失败和退出均恢复原值，保留其他标志及用户期间的设置变化。若当前系统无法可靠连续定位或恢复设置，停止整理并明确反馈，不能交付瞬移效果冒充平滑搬运。

Shell COM 操作在专用 STA 工作线程串行执行，COM 对象和 PIDL 在所属线程持有与释放，主线程只接收托管快照和操作结果。整合已有位置读取，避免观察线程和整理线程竞争。

Unity 每帧更新表现，Shell 位置请求合并为最新一项，最多约 30 次/秒，不建立无限队列。工作线程执行前再次检查输入空闲、会话代次和取消状态。暂停或取消使旧请求失效；继续前确认最后实际位置，不让延迟写入覆盖用户调整。

## 外部变化与故障

输入导致的暂停期间，如果用户改变图标、增删项目或改变布局设置，废弃旧任务并重新读取、规划；不能恢复旧快照覆盖用户操作。分辨率、工作区变化或 Explorer 重启也使旧会话失效。

每次抓取前核对项目存在及源位置。删除、位置冲突、设置不支持属于可恢复分支，停止当前计划并低频重试；COM 故障释放会话，不无限逐帧重试。位置写入成功并读回确认后才推进为已完成。

运行日志记录整理批次结果、数量、失败阶段和异常，不输出完整路径或文件名。正常空桌面、无需调整和用户暂停不重复告警；相同故障只在适配边界记录一次。状态反馈复用现有预览状态和原生菜单只读标签，菜单不承担启动功能。

## 代码边界

- Core：新增桌面项目快照、确定性分类布局与搬运状态机，不依赖 Unity 或 COM；负责可测的计划、阶段、暂停和失效规则。
- Windows：DesktopIcons 管理 Shell 会话，NativeWindow 增加最后输入时间读取和必要状态展示；原生输入仅取得空闲信息。
- Runtime：新增整理编排组件，对接 Core、Shell 和动画；DesktopPetController 只负责启动、优先级和状态连接；PrototypePet 增加叼持与低头抓放的表现参数。
- Tests / tools：扩展现有纯 C# 检查与 EditMode 测试，原有只读 Windows 探测保持只读。真实写入验收使用明确的独立测试入口，不在普通测试启动时整理用户桌面。
- README、验收清单与验证记录同步说明自动规则、系统限制和实际完成的检查。

## 验证与交付标准

1. 纯逻辑检查：分类与稳定排序、同名不同项目、工作区与间距、容量不足、占位交换、无变化不重复搬运、仅处理变化项目。
2. 状态机检查：未满 30 秒不启动；鼠标移动或按键后停止推进；再次空闲继续；暂停无时间补算；取消使旧写请求失效；外部变化重建计划。
3. 原生适配检查：Core 和 Windows 源码编译通过，只读探测成功；模拟执行器验证拒绝写入、延迟响应、取消和释放，不依赖用户桌面生成测试结果。
4. Unity 检查：编译和 EditMode 测试通过，自动演示完整播放走近、抓取、叼持行走、放下，检查边缘和不同方向的接触；暂停与恢复没有瞬移，原有互动仍可打断。
5. Windows 构建验收：在指定测试图标上验证实际位置平滑改变、图标名称及路径不变、自动排列阻止行为、网格对齐恢复、用户输入暂停、Explorer 和工作区变化后的恢复。记录帧率及明显卡顿情况；编译通过不能代替该项。

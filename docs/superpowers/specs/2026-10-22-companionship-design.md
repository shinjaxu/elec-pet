# 桌宠长期陪伴：关系、小窝、玩具与存档

日期：2026-10-22

## 目标与范围

用户已选择长期陪伴与养成，并要求按讨论方案实现。本轮交付三个关系阶段、一个固定小窝、一个小球玩具与可靠的本地存档。成功标准是用户能从行为观察到关系变化，宠物有自主玩耍和回窝休息的连续生活过程，重启后保留关系和物件位置。

沿用 Unity、Windows 主屏幕、程序化幼龙与现有透明窗口。精力和心情启动时恢复，离线不扣关系、不补算需求。旅行、多物种、外观成长、聊天、联网和商业化不进入本轮。

## 关系阶段

沿用现有 0–1 熟悉度，阶段由熟悉度直接推导，不保存第二套进度。默认阈值为初识小于 0.1、熟悉从 0.1 到小于 0.35、信任从 0.35 起。这是首版体验参数，后续按实测调整。

- 初识：保留注视、短距离玩耍与被动抚摸，不主动贴近休息。
- 熟悉：保留低频挥爪招呼；摸头时明显凑头迎合，表达亲近。
- 信任：鼠标在适当范围稳定停留后，宠物偶尔主动靠近，在安全距离趴下休息。

温柔互动仍每两秒累计一次，避免帧率影响成长。现有熟悉度增长速度保持不变，不因重复点击或离线而降低关系。主动靠近设置活动时间冷却；鼠标移动、按键、抚摸、提起均能取消接近，防止持续追逐。用户在其他窗口打字时无需读取文本或窗口内容。

编辑器预览显示当前关系阶段便于验证；Windows 右键菜单提供只读阶段标签，不展示数值进度条。

## 固定小窝

启动时显示低矮窝垫，使用程序化几何体，保持与原型风格一致。优先将旧存档中的首次休息位置用作小窝位置；新用户在工作区底部安全范围生成默认位置。

小窝支持按住拖动，松手后固定，保存为工作区内的归一化位置。缩放、分辨率或工作区变化后重新映射并约束安全边距。物件不读取或修改桌面文件。

精力不足时，宠物先走到小窝，再进入现有卧躺或睡眠姿态，并持续恢复精力。到达目标前不播放睡眠姿态；休息结束后再恢复巡游。精力过低时回窝优先于自主玩耍和图标观察。抚摸或提起立即打断回窝，互动完成后重新判断是否需要休息。

拖动小窝时取消旧位置的回窝目标，下一次行为判断使用新位置。

## 小球玩具

启动时在小窝附近放置一个彩色小球，用户可拖动摆放，位置与小窝独立保存。玩具始终限制在主屏幕工作区安全范围，不与真实桌面图标发生物理交互。

精力足够且没有用户互动时，宠物以低频机会启动一段完整过程：接近小球、歪头观察、伸爪轻碰、小球短距离滚动、结束后恢复自由活动。小球运动使用确定的受限轨迹，不引入物理碰撞系统。暂停或隐藏同时冻结宠物与小球。

玩耍存在活动时间冷却，避免抢走所有自由活动。首版仅一个玩具，不增加背包、商店、喂养或多玩具管理。玩具偏好和叼回小窝留待后续，本轮先验证自主玩耍的可读性。

## 行为与输入协调

按优先级处理：暂停或隐藏、用户直接互动、当前短动作、低精力回窝、信任后的靠近休息、玩球、图标观察与巡游。回窝和玩球的接近阶段同样属于自主流程，不允许随机闲置动作中途夺走控制。

保留现有触碰、抚摸、提起、扑食与紧急快捷键。模型命中检测扩展为宠物、小窝和小球三类，按命中对象分别处理拖动；物件不会触发宠物被提起或增加熟悉度。交互区域只覆盖实际物件及拖动期间，其他区域继续鼠标穿透，不抢键盘焦点。

## 本地存档

使用 Application.persistentDataPath 下的带版本 JSON 文件，保存熟悉度、摸头偏好、小窝位置、小球位置。暂不引入 SQLite，数据量和访问方式尚不需要数据库。

首次无 JSON 存档时读取现有 PlayerPrefs 关系和休息位置，成功写入新存档后以 JSON 为准，旧键不删除。旧位置由屏幕比例转换到当前工作区，再约束安全边距。

仅在数据变化时每 30 秒保存一次；物件拖动结束、应用退出时也保存。暂停和隐藏不推进关系或冷却，但不阻止已产生的数据落盘。文件使用同目录临时文件完成写入，再替换主文件，并保留上一份有效备份。

主文件损坏时尝试备份；两份均不可用时保留损坏文件并恢复默认状态，记录一次带失败阶段的警告，不能静默覆盖仅存的损坏数据。保存失败保留脏标记以便下一周期重试，记录异常堆栈；成功后恢复正常保存频率。读取时检查版本、数值范围和有限坐标，不接受 NaN 或无穷大。

精力、心情、正在执行的动作和离线时长不存储。异常强制结束时最多丢失最近一个自动保存周期的关系进度；拖动完成的位置在该次保存成功后即受保护。

## 代码职责

- Core：关系阶段、自主生活阶段与冷却规则、存档数据和文件读写；保持不依赖 Unity，便于独立测试。
- Runtime：程序化小窝与小球、对象命中、屏幕位置转换、行为目标移动、动画与定时保存。DesktopPetController 保留输入和更新编排，具体生活流程与物件表现放入职责明确的类。
- Windows：仅扩展菜单阶段标签，沿用透明窗口与全局快捷键。
- Tests：扩展现有独立检查入口，并添加 Unity 表现和流程测试。

不为本轮引入通用插件框架、事件总线或可配置行为树。

## 验证与验收

1. 先为三个阶段边界和互动累计、信任靠近的冷却与打断编写失败测试，再实现；保留现有互动检查。
2. 生活流程测试覆盖回窝优先级、到窝后才睡眠、玩球阶段推进、用户打断、暂停或隐藏不推进、目标变化与极小工作区约束。
3. 使用临时目录验证存档往返、旧数据迁移、损坏主文件恢复备份、两份损坏保留原文件、非法数据和保存失败后重试。
4. Unity EditMode 验证程序化物件、命中分类、拖动与位置映射、休息和玩球动作衔接；使用真实相机导出预览并检查。
5. 运行独立 Core 检查、Unity EditMode 测试并构建 Windows x64。更新 README、验证记录与实机验收清单。
6. 真实桌面检查宠物与物件点击穿透、不抢焦点、隐藏恢复、退出重启及不同缩放比例；未执行的项目明确标注，不用自动测试替代实机结论。
